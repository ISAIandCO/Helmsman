# Сборка и проверка

## Доступная среда разработки

На этапе первоначальной разработки: Linux x86_64 в контейнере, без /dev/net/tun и CAP_NET_ADMIN. Политика окружения запрещает Unix/netlink sockets. Поэтому запуск sing-box упирается в `create netlink socket: operation not permitted` ещё до сетевого handshake. Это ограничение среды; фактические сетевые испытания перенесены в GitHub Actions и не подменяются успешной проверкой JSON.

Локально выполнены:

- Python syntax/compile checks и unit-тесты разбора форматов, запрета hooks/file paths, HWID, защиты redirect, атомарности подписок, сохранения ID/HWID и компиляции правил/DNS.
- `sing-box check` для создаваемых VLESS, Hysteria2, WireGuard, OpenVPN и AmneziaWG конфигураций (в том числе реальный Throne fork).
- TypeScript `tsc --noEmit` и Rollup-сборка Decky.
- Рендер семи страниц Qt GUI при разрешении 1280×800 и основных экранов при 960×600; навигация, connect/disconnect, сохранение DNS и подписки/HWID, открытие дополнительных настроек, WARP consent. Скриншоты создаются в QA-artifact на синтетических профилях и не являются снимками подключения к провайдеру.
- Сборка сетевого Throne fork из закреплённых исходников и ZeroTier MPL Agent без nonfree controller.

GitHub Actions выполняет дополнительные проверки до публикации. Итоговый статус и конкретные выполненные тесты следует брать из успешного run нужного commit; незавершённая сборка не считается проверкой. При наличии ограничений sockets в обычном контейнере тесты помечаются skipped, но **в CI это ошибка**, а не пропуск.

## Что делает GitHub Actions

1. Собирает оба закреплённых sing-box из source с минимальными build tags, Xray-core и wgcf из закреплённых исходников, MPL ZeroTier Agent, Qt-приложение/сервис и Decky frontend.
2. На настоящем HTTPS-сервере с тестовым CA проверяет параметры NekoBox_SF (включая модель с пробелом), User-Agent, gzip/Base64, сохранённый HWID, ручное обновление и расписание через Controller, ответы HWID required/лимит устройств, ограничение размера распаковки и сохранение профилей при отказе. Проверяет клиентские массивы JSON TCP/WS/gRPC/XHTTP настоящим sing-box check и сохранение новых полей в GUI. Проверяет контракты HWID/подписок, хранение настроек, общую Unix RPC-службу через desktop-клиент и Python backend Decky.
3. Проверяет все готовые DoH/DoT конфигурации обоими движками, выполняет реальные TLS DNS-запросы напрямую и через SOCKS с тестовым CA, проверяет нестандартный путь/параметры и сохранение настроек при неверном DNS URL. Передаёт настоящий TCP-трафик через локальный клиент и локальный сервер VLESS (TCP/WS), VMess, Shadowsocks, Trojan, Hysteria1/2, TUIC, AnyTLS, WG/AWG и OpenVPN. Дополнительно передаёт TCP/UDP через XHTTP/TLS во всех четырёх режимах, XHTTP/REALITY и отдельный downloadSettings, проверяет VMess/Trojan XHTTP; TCP/UDP и параллельные TCP-потоки через нативный mux VLESS/VMess/Trojan с TCP/WS/gRPC/HTTPUpgrade, VLESS REALITY без Vision, XUDP при отключённом TCP mux, XHTTP с XUDP; AWG-клиент с публичным WARP I1/junk-шаблоном соединяется с обычным WG-сервером. Это локальные fixtures, не тест провайдера или Cloudflare.
4. Создаёт две изолированные Linux network namespaces. Проверяет TUN TCP/UDP, DNS/FakeIP, блокировку домена/IP, аварийное завершение движка, отсутствие прямого выхода при существующем физическом маршруте, восстановление и очистку; повторяет TUN/DNS/UDP через XHTTP/SOCKS, аварийно завершает Xray, проверяет остановку TUN и сохранение guard, восстановление и остановку обоих процессов. Повторяет TUN/DNS/UDP, общую RPC-службу и защиту при аварии для TCP mux, импортированного из Xray JSON.
5. На реальных tmpfs проверяет отказ при заполненном разделе установки без изменения старой версии и настроек, а также копирование полного пакета и состояния в `/opt` с нетронутым 16 МиБ `/var`. Проверяет права root и отказ от подмены каталога ссылкой. Проверяет состав устанавливаемых архивов и SHA256SUMS, запускает извлечённый GUI через offscreen, X11/Xvfb и нативный Wayland/Weston headless (с проверкой фактического QPA), устанавливает пакет как systemd-службу, обращается к ней от обычного пользователя, проверяет TUN/защиту из frozen-приложения, повторную установку с сохранением профилей/HWID/DNS и удаление. Все установки выполняются с `--decky` в root-owned `homebrew/plugins` без записи для обычного пользователя; проверяются чтение файлов непривилегированным backend, обновление/удаление плагина и сохранность соседнего плагина. Эта проверка установленного TUN использует недоступный тестовый сервер и не считается handshake-тестом. Публикует prerelease только после успешных этапов.

## Повторить сборку

На Ubuntu 22.04 x86_64 установите build-essential, git, Python 3.12.12, Go 1.26.8, Node 22.21.1, nftables, iproute2, Qt runtime prerequisites. Обычный пользователь:

```bash
python -m venv .venv
source .venv/bin/activate
pip install '.[gui,build]'
python scripts/build-engines.py
cd decky
npm ci --ignore-scripts
npm run check
npm run build
cd ..
HELMSMAN_ENGINES="$PWD/build/engines" python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen python scripts/check-gui.py
sudo env HELMSMAN_ENGINES="$PWD/build/engines" bash scripts/test-netns.sh "$(command -v python)"
python scripts/runtime-sources.py
python scripts/package.py
# Для packaged Wayland QA нужен weston и libwayland-egl1.
python scripts/check-artifacts.py
sudo env HELMSMAN_CI=1 "$(command -v python)" scripts/check-storage.py
python scripts/check-install.py
```

Версии исходников и зависимости закреплены; `BUILD.json` указывает toolchain, commit и состав. Это воспроизводимая процедура сборки с закреплёнными входами, **не обещание побитового совпадения** архивов на разных хостах: версии системного компилятора, timestamps и PyInstaller bootloader могут влиять на байты. В engine-sources есть vendored Go-зависимости для пересборки без загрузки модулей.

## На физическом Steam Deck: короткий приёмочный прогон

Физического устройства и пользовательских серверов на этапе разработки нет. До использования как основного VPN:

1. Установить архив на актуальной SteamOS, открыть GUI, импортировать тестовый профиль. Подключить и выполнить встроенную проверку. Проверить адрес выхода в своей инфраструктуре, IPv4/IPv6, DNS. Повторить для реального сервера каждого нужного протокола, отдельно REALITY/Vision, Hysteria1/2, AWG нужного поколения и OpenVPN провайдера.
2. Открыть Game Mode: состояние/профиль должны совпадать с GUI. Проверить A/B, D-pad/стики, dropdown, подключение/отключение и обновление подписки. Вернуться в Desktop Mode — соединение сохраняется.
3. Подключить тестовую подписку: общий/ручной HWID, Remnawave и header/query. На своём сервере проверить входящие поля. Вернуть HTTP 500, HTML, пустой ответ, невалидный или смешанный профиль — рабочие узлы/выбранный профиль должны сохраниться.
4. Проверить полный и оба российских пресета, собственное правило block/direct/proxy и порядок, импорт/ошибку обновления списка. При желании проверить Linux process_name/path на обычном процессе и отдельно Proton; App ID не заявлен.
5. Запустить загрузку Steam, сетевую игру и голосовой чат, проверить UDP и MTU. Проверить Remote Play и доступ к LAN; выключить LAN и повторить. Зафиксировать конкретные игры/античит — универсальных гарантий нет.
6. Оборвать сеть и завершить engine-процесс через root. Внешний трафик должен остановиться, разрешённая LAN остаться. Восстановить сеть/перезапустить сервис и проверить восстановление. Кнопка «Отключить» должна вернуть прямой доступ.
7. Сон/пробуждение, смена Wi-Fi → Ethernet → Wi-Fi, перезапуск службы, смена Desktop/Game, перезагрузка SteamOS: HWID сохраняется; при auto_connect=false VPN остаётся отключённым, при auto_connect=true выбранный профиль запускается и ранний guard ставится до NetworkManager. Проверить оба значения независимо от последнего ручного disconnect. Проверить журналы загрузки, реальную утечку пакетов при reboot — локальный unit-тест этого не доказывает.
8. ZeroTier: подключиться к своей закрытой сети, увидеть Node ID/ACCESS_DENIED, разрешить устройство, получить OK/адрес и доступ к peer. Проверить отключение и отсутствие навязанных default/global/DNS маршрутов. Смешивание с другим VPN не поддерживается.
9. Поверх установленной версии поставить новую, проверить сохранение данных; удалить без --purge, проверить прямой доступ, отсутствие helmsman0/таблицы 31800/firewall и плагина; установить снова, проверить профили/HWID.
10. Измерить CPU/RAM в простое/под нагрузкой и расход батареи; они не измерены на устройстве. Проверить поведение после обновления SteamOS.

Неподтверждённые области: аппаратный Steam Deck, Game Mode runtime Decky/конкретная версия Steam UI, сон/энергопотребление, поведение ранней загрузки SteamOS, внешняя ZeroTier Central-авторизация, реальные провайдеры и межреализационная совместимость AWG 3.x. Наличие исходников/пункта интерфейса не объявляется успешным испытанием этих сценариев.

## Проверка XHTTP и WARP

Локально в этой среде Xray 26.10.17 собран из закреплённого source с Go 1.27.2. Проверены настоящие TCP/UDP в auto/packet-up/stream-up/stream-one через TLS, отдельный downloadSettings с hostname, VMess/Trojan XHTTP и настоящий XHTTP/REALITY TCP/UDP, отказ неправильного SOCKS-пароля и схемы TLS/REALITY. Приватный `.conf` warpgen, предоставленный пользователем, разобран с сохранением I1/J/H/S и принят `sing-box-awg check`; файл и ключи не добавлены в репозиторий. В CI используется синтетический аналог структуры и публичная MIT-сигнатура.

Контракт генератора проверяется с контролируемым CLI fixture: явное согласие, повторное использование account, права 0600, выбор AWG/WG/endpoint, отсутствие вывода ключей, сохранение прежних данных при ошибке и отсутствие дубликатов. Эти проверки не регистрируют учётную запись Cloudflare. Внешняя регистрация wgcf и handshake с Cloudflare остаются неподтверждёнными.

На Steam Deck: импортировать свой XHTTP URI с реальными параметрами TLS/REALITY, проверить Steam Store и UDP-игру; завершить Xray и убедиться в восстановлении/блокировке без прямого выхода. Для WARP импортировать свой warpgen .conf, выбрать профиль и проверить интернет/UDP; затем в Desktop или Decky принять условия Cloudflare и создать профиль AWG, при необходимости указать доступный endpoint. Повторить создание: аккаунт сохраняется, идентичный профиль не дублируется. Условия регистрации и работоспособность маскировки зависят от внешнего сервиса и сети; не следует выдавать успешный локальный fixture за успешный обход блокировки.

Совместимость с личной подпиской VLESS+ не заявляется проверенной: URL/ответ провайдера не предоставлен. Приёмка: перенести параметры и User-Agent из рабочей настройки NekoBox_SF, сохранить и обновить, проверить список узлов; повторить из Decky и после перезапуска. При отказе зафиксировать безопасное сообщение ошибки (HTTP-код/категорию HWID/формат), без приватного URL и тела подписки.

## Desktop / Wayland и mux: приёмка alpha.6

Локально проверены настоящие mux TCP/UDP и параллельные потоки через закреплённый Xray. В GitHub Actions дополнительно обязательны полный TUN и упакованный Wayland-клиент; результат конкретной сборки указан в Actions. Weston headless подтверждает загрузку Qt Wayland и открытие окна, но не проверяет KWin, экранную клавиатуру, жесты или игровой runtime.

На Steam Deck: открыть новую версию в KDE Wayland, проверить семь разделов, прокрутку подписки/дополнительных параметров, фокус клавиатуры, ввод через экранную клавиатуру, выбор своего DNS. Для контроля платформы можно запустить `QT_QPA_PLATFORM=wayland /opt/helmsman/current/Helmsman --smoke-test` из Konsole: ожидается `Helmsman Qt platform: wayland`. Затем обновить сохранённую подписку и подключить профиль с mux; проверить Steam Store и UDP-игру, отключить из Decky. При ошибке экспорта XHTTP/Vision с TCP Mux.Cool запросить у провайдера совместимую конфигурацию (`concurrency=-1` или отключённый TCP mux); не отключать проверку TLS. Отрицательный тест с настоящим XHTTP и обычным TCP mux воспроизводит отказ закреплённого upstream (`unexpected network TCP`), поэтому эта комбинация отклоняется заранее с объяснением, без скрытой правки параметров.

## Компактный Decky и автоподключение: alpha.7

CI собирает TypeScript/Rollup-плагин с фиксированным SVG 20×20, скрытыми по умолчанию дополнительными пунктами и штатными фокусируемыми элементами Decky. В Python проверяются отдельная опция, миграция старых настроек без потери активного сеанса, новая загрузка с auto_connect on/off, одинаковая политика ранней защиты и daemon, сохранение HWID, восстановление после сбоя при auto_connect=false и отказ неверному типу параметра. Проверяется общая настройка через Desktop RPC и настоящий backend Decky. Установленный frozen-сервис в systemd проверяется с имитацией смены boot_id: опция off оставляет TUN и guard выключенными; on включает выбранный тестовый профиль и guard. Это не аппаратная перезагрузка CI-хоста. Изменение настройки не меняет PID уже работающих движков. Перезапуск службы в текущей загрузке восстанавливает вручную включённый VPN даже при выключенной опции.

Приёмка на Deck: проверить высоту пункта Helmsman в списке Decky, раскрытие/сворачивание «Дополнительно» и WARP кнопкой A, переход фокуса D-pad/стиками. Открыть/закрыть плагин с отключённым VPN — VPN не должен включаться. Проверить переключатель из Decky и Desktop, затем обе аппаратные перезагрузки с off/on. Проверить, что переход Game/Desktop и сон сохраняют уже активное соединение. Реальный Steam UI/Decky runtime и физическая загрузка SteamOS в контейнерной CI не проверяются.

## Импорт смешанной Xray-подписки и высота Desktop: alpha.8

Проверяются смешанные массивы Xray JSON с VLESS, Shadowsocks, SOCKS5, HTTP CONNECT, базовым Hysteria2 и служебным Loopback; плоские и legacy settings, опциональные null, исходные учётные данные, HTTP-заголовки, TLS и mux. Реальный HTTPS fixture с тестовым CA требует прежние NekoBox/HWID/User-Agent заголовки, возвращает gzip/Base64 JSON и проверяет сохранение всей предыдущей конфигурации при неизвестном типе. В ошибке проверяются точный путь JSON и отсутствие приватных имён/URL/паролей/HWID.

Локальные Xray-клиент/сервер передают настоящий TCP/UDP для импортированных Shadowsocks AEAD/SS2022 и SOCKS5 через TLS; HTTP CONNECT — TCP через TLS; Shadowsocks/SOCKS/HTTP с mux — параллельные TCP (UDP там, где поддерживается). В GitHub CI отдельно выполняется путь через основной sing-box для plain native Xray Shadowsocks/SOCKS/HTTP и Hysteria2 с частным тестовым CA. Это контролируемые серверы, а не личная подписка пользователя.

Qt GUI получает реальный доступный размер экрана и уменьшает исходный размер окна с запасом под оформление KDE. Главная страница проверяется по фактическому maximum вертикальной полосы прокрутки (=0), а не только по снимку: 1280×720, 1180×688, 1060×650, 960×600. Скриншоты desktop-fit-* входят в QA artifact. Аппаратные масштабирование KDE, рамка KWin и экранная клавиатура требуют проверки на Deck. Очень длинные диагностические сообщения могут требовать прокрутки; обычный экран подключения должен помещаться.
