# Совместимость

«Реализовано» означает импорт, проверку конфигурации движком, запуск, остановку и обработку ошибки. Проверки локального клиента с локальным сервером не доказывают совместимость со всеми провайдерами. Фактические испытания см. в TESTING.md и журнале GitHub Actions.

Все типы профилей используют общий API сервиса. Ошибка запуска, завершение процесса, отказ проверки конфигурации и ошибки подписок показываются без публикации исходных ключей. Статус `running` для интернет-VPN подтверждает процесс/TUN, а не удалённую доступность. Для неё предусмотрена отдельная TCP/TLS-проверка.

Подписки: UTF-8 список URI, Base64 списка URI, массив outbound JSON, sing-box/Xray JSON с outbounds/endpoints. Импортируются соединения; маршрутизация, services/inbounds и чужая системная политика не импортируются. Freedom/Blackhole/DNS/Loopback и sing-box selector/urltest исключаются как чужая политика, а не удалённые серверы. Неизвестный узел в подписке отклоняет обновление целиком, чтобы не терять данные молча; JSON-ошибка указывает путь с индексами от нуля без содержимого профиля. Clash YAML, QR-коды и зашифрованные архивы в первой версии не разбираются.

Сочетания: один основной sing-box (с одним Xray-процессом для XHTTP/mux или TLS/транспорта Shadowsocks/SOCKS) **или** один AWG sing-box **или** один ZeroTier Agent. Фоновые процессы не запускаются заранее. Пользователь может выбрать любой интернет-профиль для всех VPN-правил; разные VPN-профили в отдельных правилах одновременно пока не поддерживаются.


Подписки: URI/список Base64, sing-box JSON, массивы клиентских конфигураций с outbounds, Xray JSON для VLESS/VMess/Trojan с TCP/raw, WS, gRPC (без multiMode), HTTP/HTTPUpgrade и XHTTP. Из полных конфигураций извлекаются только соединения; inbounds/API/routing не применяются. Xray mux сохраняется и выполняется нативным Xray для VLESS/VMess/Trojan: TCP/raw, WS, gRPC без multiMode, HTTPUpgrade; поля enabled/concurrency/xudpConcurrency/xudpProxyUDP443. TCP Mux.Cool с XHTTP или Vision отклоняется с точной причиной: нужен concurrency=-1 (XUDP) или отключённый mux. HTTP/H2 с mux не заявляется; проверка закреплённым движком обязательна. Неподдерживаемые/небезопасные поля отклоняются. Отдельные настройки User-Agent и параметров HWID применяются одинаково при ручном обновлении, по расписанию и из Decky. Полный ответ проходит проверку движком до замены профилей. Clash YAML требует другого формата экспорта; сообщение об ошибке предлагает сменить User-Agent.

Xray JSON: дополнительно проверены Shadowsocks AEAD/SS2022, SOCKS5 и HTTP(S) CONNECT, обе схемы settings (servers и плоские address/port), опциональные null mux/streamSettings. Один сервер и не более одного аккаунта на профиль; внешние dialerProxy/sockopt и файловые параметры не импортируются. TLS/дополнительный транспорт Shadowsocks и SOCKS выполняется Xray, обычные профили — основным sing-box. HTTP CONNECT имеет только TCP/TLS, произвольный UDP не поддерживает; Mux.Cool требует соответствующего сервера. Xray protocol=hysteria — только Hysteria2 с settings.version=2, transport Hysteria/version=2, TLS и auth; нестандартный UDP idle timeout, серверный masquerade и mux не переносятся, для них нужен поддерживаемый URI/sing-box JSON. Hysteria1 остаётся отдельным протоколом. Наличие loopback не импортирует цепочки или чужой routing.

## Xray streamSettings и socket options (alpha.9)

Нативный импорт принимает пустые/null экспортируемые блоки kcpSettings, quicSettings, dsSettings, gunSettings, masqueSettings, xdriveSettings, xtlsSettings и finalmask. Это не поддержка активных mKCP/QUIC/MASQUE/XDRIVE/старого XTLS/FinalMask. Непустой неподдерживаемый блок отклоняется по имени. Принимается псевдоним `websocket`; `method` имеет приоритет над `network`, `rawSettings` — над `tcpSettings`, как в закреплённом Xray.

Поддерживаемые `sockopt`: `tcpFastOpen`, `tcpKeepAliveIdle`, `tcpKeepAliveInterval`, `tcpUserTimeout`, `tcpMaxSeg`, `tcpWindowClamp`, `tcpCongestion` (bbr/cubic/reno), `happyEyeballs`, `domainStrategy`. TCP-параметры сохраняются в `xray_sockopt` и принудительно выбирают существующий Xray sidecar, в том числе без mux/XHTTP. Проверка типов/диапазонов выполняется до обновления подписки; настройки повторно проверяются при загрузке профиля. Для happyEyeballs допускаются задержка 0–60000 мс, interleave 0–16, maxConcurrentTry 0–64. Поддержка параметра ядром и доступность алгоритма TCP зависят от SteamOS. Дополнительные sockopt для нативного Hysteria2 не переносятся.

Пустые/default mark/interface/dialerProxy/tproxy/customSockopt/прочие системные поля принимаются как выключенные. Активные изменения маршрутизации, внешние цепочки, произвольные socket options и SRV/TXT-переадресация не импортируются. Helmsman всегда задаёт `penetrate=true` против зацикливания TUN, использует свой bootstrap DNS, заменяет AsIs на UseIP, а при выключенном IPv6 принудительно задаёт UseIPv4. Прочие поддерживаемые Use/Force стратегии сохраняются при включённом IPv6. TLS-проверка остаётся включённой.
