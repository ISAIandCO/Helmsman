# Совместимость

«Реализовано» означает импорт, проверку конфигурации движком, запуск, остановку и обработку ошибки. Проверки локального клиента с локальным сервером не доказывают совместимость со всеми провайдерами. Фактические испытания см. в TESTING.md и журнале GitHub Actions.

Все типы профилей используют общий API сервиса. Ошибка запуска, завершение процесса, отказ проверки конфигурации и ошибки подписок показываются без публикации исходных ключей. Статус `running` для интернет-VPN подтверждает процесс/TUN, а не удалённую доступность. Для неё предусмотрена отдельная TCP/TLS-проверка.

Подписки: UTF-8 список URI, Base64 списка URI, массив outbound JSON, sing-box/Xray JSON с outbounds/endpoints. Импортируются соединения; маршрутизация, services/inbounds и чужая системная политика не импортируются. Freedom/Blackhole/DNS/Loopback и sing-box selector/urltest исключаются как чужая политика, а не удалённые серверы. Неизвестный узел в подписке отклоняет обновление целиком, чтобы не терять данные молча; JSON-ошибка указывает путь с индексами от нуля без содержимого профиля. Clash Meta YAML/JSON со списком proxies поддерживается; QR-коды, внешние proxy-providers и зашифрованные архивы не разбираются.

Сочетания: один основной sing-box (с одним Xray-процессом для XHTTP/mux или TLS/транспорта Shadowsocks/SOCKS) **или** один AWG sing-box **или** один ZeroTier Agent. Фоновые процессы не запускаются заранее. Пользователь может выбрать любой интернет-профиль для всех VPN-правил; разные VPN-профили в отдельных правилах одновременно пока не поддерживаются.


Подписки: URI/список Base64, sing-box JSON, массивы клиентских конфигураций с outbounds, Xray JSON для VLESS/VMess/Trojan с TCP/raw, WS, gRPC (без multiMode), HTTP/HTTPUpgrade и XHTTP. Из полных конфигураций извлекаются только соединения; inbounds/API/routing не применяются. Xray mux сохраняется и выполняется нативным Xray для VLESS/VMess/Trojan: TCP/raw, WS, gRPC без multiMode, HTTPUpgrade; поля enabled/concurrency/xudpConcurrency/xudpProxyUDP443. TCP Mux.Cool с XHTTP или Vision отклоняется с точной причиной: нужен concurrency=-1 (XUDP) или отключённый mux. HTTP/H2 с mux не заявляется; проверка закреплённым движком обязательна. Неподдерживаемые/небезопасные поля отклоняются. Отдельные настройки User-Agent и параметров HWID применяются одинаково при ручном обновлении, по расписанию и из Decky. Полный ответ проходит проверку движком до замены профилей. Clash Meta запрашивается по умолчанию; пользовательский User-Agent можно сохранить для другого формата.

Xray JSON: дополнительно проверены Shadowsocks AEAD/SS2022, SOCKS5 и HTTP(S) CONNECT, обе схемы settings (servers и плоские address/port), опциональные null mux/streamSettings. Один сервер и не более одного аккаунта на профиль; внешние dialerProxy и файловые параметры не импортируются; поддерживаемые sockopt описаны ниже. TLS/дополнительный транспорт Shadowsocks и SOCKS выполняется Xray, обычные профили — основным sing-box. HTTP CONNECT имеет только TCP/TLS, произвольный UDP не поддерживает; Mux.Cool требует соответствующего сервера. Xray protocol=hysteria — только Hysteria2 с settings.version=2, transport Hysteria/version=2, TLS и auth; нестандартный UDP idle timeout, серверный masquerade и mux не переносятся, для них нужен поддерживаемый URI/sing-box JSON. Hysteria1 остаётся отдельным протоколом. Наличие loopback не импортирует цепочки или чужой routing.

## Xray streamSettings и socket options (alpha.9)

Нативный импорт принимает пустые/null экспортируемые блоки kcpSettings, quicSettings, dsSettings, gunSettings, masqueSettings, xdriveSettings, xtlsSettings. Это не поддержка активных mKCP/QUIC/MASQUE/XDRIVE/старого XTLS. Непустой неподдерживаемый блок отклоняется по имени. Принимается псевдоним `websocket`; `method` имеет приоритет над `network`, `rawSettings` — над `tcpSettings`, как в закреплённом Xray.

Поддерживаемые `sockopt`: `tcpFastOpen`, `tcpKeepAliveIdle`, `tcpKeepAliveInterval`, `tcpUserTimeout`, `tcpMaxSeg`, `tcpWindowClamp`, `tcpCongestion` (bbr/cubic/reno), `happyEyeballs`, `domainStrategy`. TCP-параметры сохраняются в `xray_sockopt` и принудительно выбирают существующий Xray sidecar, в том числе без mux/XHTTP. Проверка типов/диапазонов выполняется до обновления подписки; настройки повторно проверяются при загрузке профиля. Для happyEyeballs допускаются задержка 0–60000 мс, interleave 0–16, maxConcurrentTry 0–64. Поддержка параметра ядром и доступность алгоритма TCP зависят от SteamOS. Нативный Hysteria2 с sockopt/FinalMask выполняется через Xray; обычный Hysteria2 остаётся в sing-box.

Пустые/default mark/interface/dialerProxy/tproxy/customSockopt/прочие системные поля принимаются как выключенные. Активные изменения маршрутизации, внешние цепочки, произвольные socket options и SRV/TXT-переадресация не импортируются. Helmsman всегда задаёт `penetrate=true` против зацикливания TUN, использует свой bootstrap DNS, заменяет AsIs на UseIP, а при выключенном IPv6 принудительно задаёт UseIPv4. Прочие поддерживаемые Use/Force стратегии сохраняются при включённом IPv6. TLS-проверка остаётся включённой.

## FinalMask (alpha.10)

Нативный `streamSettings.finalmask` сохраняется в `xray_finalmask` и передаётся штатному Xray. Поддерживаются VLESS, VMess, Trojan, Shadowsocks, SOCKS5, HTTP CONNECT и Hysteria2; фактический TCP/UDP-транспорт определяется протоколом/режимом. Список TCP-масок не изменяет автоматически UDP, и наоборот. Порядок слоёв сохраняется. Неактивные `tcp: []`, `udp: []` и null не создают отдельный sidecar. Система по-прежнему допускает один выбранный VPN; DNS/rules/guard не импортируются из чужой конфигурации.

| Направление | Поддерживается | Проверка |
| --- | --- | --- |
| TCP | fragment: packets, length/delay либо lengths/delays, maxSplit | Реальные TLS TCP/UDP-запросы через VLESS RAW и XHTTP; TUN с TCP fragmentation, mux и socket options |
| TCP | sudoku; header-custom, включая capture/reuse/байтовые transform | Реальные согласованные Xray-клиент/сервер, TCP/UDP через VLESS/TLS |
| UDP | salamander, в том числе packetSize/gecko | Обычный Salamander: реальные TCP/UDP через Hysteria2 и VLESS XHTTP/H3. Gecko отдельно на проводе не проверен |
| UDP | header-custom, mkcp-legacy, noise (список элементов/exp), sudoku | Проверка схем закреплённым Xray; совместимость с конкретными серверами на проводе отдельно не подтверждена |
| QUIC | Поля quicParams закреплённого движка: congestion/bbrProfile, brutalUp/Down, окна, idle/keepalive/MTU/GSO и остальные перечисленные в коде поля | Реальные Hysteria2/XHTTP H3 с BBR и maxIdleTimeout. Прочие параметры проходят нативную проверку, отдельный нагрузочный тест не проведён |
| XHTTP downloadSettings | Свой finalmask для отдельного канала загрузки | Сохранение и компиляция; маскированный отдельный download-канал на проводе не проверен |

Только настройки данных: файлы, Lua noise.script, включение QUIC debug, Realm, XDNS, ICMP, UDPHop и XMC не импортируются. Ошибка называет распознанный тип/поле без приватного значения. Legacy quicParams.udpHop не поддерживается закреплённой схемой; он не передаётся молча как игнорируемое ядром поле. Для HTTP/H2, удалённого из современного Xray, сочетания с FinalMask не заявляются. Hysteria2 с масками требует native Xray JSON, version=2 и TLS, без sing-box up/down/obfs/hopping и server masquerade. Проверка движком выполняется до замены подписки.


## Clash Meta и TLS (alpha.11)

Запрос подписки по умолчанию предпочитает Clash Meta, как NekoBox_SF. Ответ распознаётся по содержимому: YAML/JSON proxies, URI/Base64, sing-box или Xray JSON. Отдельные VLESS и Hysteria2 выполняются основным sing-box; XHTTP — существующим Xray. Название Xray в прежней ошибке обозначало ветку импортера, а не установленный тип удалённого сервера.

| Clash тип | Импортируемые параметры и ограничения |
|---|---|
| VLESS | UUID, Vision, packet-encoding (по умолчанию xudp), TLS/SNI/ALPN/uTLS, REALITY public-key/short-id; TCP, WS, gRPC, H2, HTTPUpgrade, XHTTP. Активный VLESS encryption пока не переносится |
| Hysteria2 | password, SNI, встроенный CA, ALPN h3, Salamander/obfs-password, up/down в целых Mbps, ports/диапазоны и hop-interval; отдельный QUIC-протокол, не транспорт VLESS |
| VMess, Trojan | Базовая аутентификация/TLS; поддерживаемые WS/gRPC/HTTPUpgrade, для VMess также H2/HTTP |
| Shadowsocks, SOCKS5, HTTP | Базовые учётные данные/шифр, TLS при наличии. Плагины Shadowsocks и внешние цепочки не импортируются |

Принимаются обычные YAML anchors/aliases с ограничениями размера/вложенности, циклы и исполняемые YAML tags отклоняются. Из полного Clash-конфига извлекаются только подключения; rules, DNS, TUN, scripts и proxy-groups не применяются. Активные interface-name/routing-mark/dialer-proxy/mptcp не переносятся. Неподдерживаемый узел отклоняет обновление целиком. Отключение проверки TLS не допускается. XHTTP принимает path/host/mode/headers и соответствующие Xray параметры padding/session/uplink/sc/reuse-settings; Clash download-settings пока не переносится (native Xray/URI extra поддерживает downloadSettings).

Нативный Xray TLS дополнен клиентскими enableSessionResumption, minVersion/maxVersion (1.2/1.3), cipherSuites, curvePreferences, pinnedPeerCertSha256 (HEX SHA256), verifyPeerCertByName, disableSystemRoot/useSystemCA и встроенными certificates с usage=verify. Расширения сохраняются в xray_tls и выполняются штатным Xray. Пустые/null экспортируемые серверные и legacy TLS/REALITY поля принимаются без активации. REALITY password имеет приоритет над publicKey, как в закреплённом Xray. Файловые ключи/сертификаты, masterKeyLog, активные серверные параметры, ECH и legacy chain pinning не импортируются. Проверка движком обязательна до замены подписки.
